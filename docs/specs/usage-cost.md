# 用量的美元估算

## 口径

为周期用量、今日用量和重置周期历史提供 USD 查看方式。USD 是本机已记录 Token 按当前已核验的 OpenAI 标准 API 价格计算的等值估算，不是订阅账单、额度换算或实际 API 付款记录。日志未提供服务档位，统一以 Standard 为比较基准，不推测 Fast、Batch、地区加价或工具调用费。价格版本随应用维护，不从网页实时抓取，不发送任务数据。

定价依据（2026-09-24 核验）：[官方价格表](https://developers.openai.com/api/docs/pricing)、[GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)、[GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)、[GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)、[GPT-5.6 Sol](https://developers.openai.com/api/docs/models/gpt-5.6-sol)、[GPT-5.6 Terra](https://developers.openai.com/api/docs/models/gpt-5.6-terra)、[GPT-5.5](https://developers.openai.com/api/docs/models/gpt-5.5)、[GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4)、[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)。只精确匹配已核验的模型标识；无已核验价格的模型保持未知，不按前缀猜测。每次准备版本时核对官方模型与价格表，并检查本机已观察到的新模型标识，避免新增模型长时间显示为未知。

仓库每天在 GitHub Actions 中只读读取官方价格页的 Markdown Standard 表，核对已支持模型的输入、缓存读取、缓存写入、输出及长上下文费率，并与已审查的 Standard 模型标识清单比较。价格变化、新标识、表格无法解析或官方站点不可用时检查失败并给出原因，不能静默宣称价格仍准确。该公开工作流不访问任何用户日志或账号，不自动修改费率或发布。维护者核对新增模型是否属于 Codex 后更新价格与清单；正式发布后现有更新机制再将修正送达安装用户。客户端对未知模型继续显示未知，不从网页实时取价。

## 采集与完整性

复用 UsageCursor：只投影 turn_context 的模型元数据、token_count 的计数、session_meta 的分叉标记及 token_usage_record 的本地用量计数，不保存对话内容。费用沿用 Token 的时间边界、累计差分去重和分叉继承排除。美元基于可证实的单次明细计算；首次基线、多次调用聚合、累计回退或明细缺失无法确定单次计价时，该部分保持未知，不拿整段累计量套用最后一个模型或上下文门槛。

新一轮任务开始后的首条有效 token_count，若当前累计值与 last_token_usage 在总量、输入、缓存读取、缓存写入和输出各字段完全相同，且总量等于输入加输出、缓存拆分不超过输入，则它证明本轮计数从一次完整调用重新起算；忽略上一轮的计数作为本轮基线，不论新数值是否大于旧数值。Token 与美元共用这一边界，避免美元金额和 Token 柱子口径不一致。没有新一轮证据或明细不匹配时仍按可验证的累计差分统计 Token，美元保持未知；不推断多次调用的模型或长上下文分段价格。若 token_count 的总量、输入和输出均为有效非负整数，但总量不等于输入加输出，该条记录不计入 Token 或美元，也不替换上一条有效基线。

分叉会话的首条累计计数可能含有父任务用量。用 session_meta 的 forked_from_id 识别分叉，并在 token_usage_record 的 thread_token_usage 与首条累计计数都完整自洽时，逐字段扣除继承基线，只统计本地增量；缺少可证实的本地基线时不把首条累计数冒充新用量，美元保持未知。任务目录直接提供分叉标记时沿用相同排除口径。

每个日/周期聚合既有数值与完整性：存在未计价的正用量则该聚合的 USD 为 null，不能把已知部分当成完整合计。明确零用量为 0；无记录为 null。未知周期显示横杠，不画为零柱。模型变化前后分别计价。复用原有尾部读取范围，不为费用扩大旧日志扫描；尾部缺少有效模型上下文的正用量保守未知，后续已知上下文的调用正常计价。相同读取范围内重放与增量结果一致。正常计数的时间边界和口径不变，不新增采集线程或全历史持久化索引。

Provider 内存快照增加 history_usd（日键）、daily_usd、普通任务 usd（日费用）、reset_events[].usd。已有 Token 字段和状态结构不改；搜索统计同步排除自相矛盾的合成计数。聚合按原范围去重，Side 不复制父任务费用。保留数据缺失的 null 语义。

## 展示

周/日面板复用 M / 100M 分段控件，加入 USD；选择即刷新原图、总和及列表数值。标题使用本地化的“估算费用”，单位只在右侧选择器显示。重置历史在原有标题位置提供“周期用量（亿）”/“估算费用（美元）”选择，单位随标题显示一次；类型图例保持在同一行，不增加详情行、长提示或百分比，不改变面板锚点、柱宽、日期轴和滚动交互。

金额最多保留两位小数，正数小于 0.01 显示 <0.01，单位在标题处统一说明。USD 与 Token 是不同指标；新增 chart_metric 设置（tokens/usd，默认 tokens），原 chart_unit 继续保存 M/100M，任务搜索的 Token 列及单位不受美元模式影响。关闭/重开与重启保留选择。

## 验收

- 手算核对缓存拆分、输出、长上下文边界、混合模型；未知模型、缺字段、不一致明细不产生虚假金额。
- 累计重复、回退、跨日、周期边界、分叉继承、首次加载与追加结果正确；Token/任务状态原有测试不回归。
- M/100M/USD 点击、键盘与持久化正确；Token 搜索不误显示美元；美元未知总和不把部分数值冒充完整合计。
- 四语言、深浅色的真实 Qt 渲染检查标题/单位/时间/图例不重叠；布局与切换保留既有动画，不使用真实鼠标或消费重置机会。构建后核对安装版与设置保留。
