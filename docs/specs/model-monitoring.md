# 后续 Codex 模型监测

## 目标

提供一个可关闭的“模型监测”模式，核对由任务栏工具接管启动的后续 Codex 会话中，服务器回报的模型与请求模型是否一致。监测结果用于诊断路由，不改变模型选择、请求内容或额度行为。

## 启动与接管

监测默认关闭。开启后进入“等待接管”状态，不中断当前任务；Provider 确认没有进行中的主任务或侧聊后，才允许工具关闭并重新启动 Codex。接管启动必须复用当前用户已安装的官方 Codex Desktop，保存当前启动方式和监测开关。当前任务仍在运行时不得强制关闭、杀进程或改变连接。

任务栏工具只保证自己启动的 Codex 会话进入监测链路。用户从开始菜单、原快捷方式或其他客户端直接启动的会话显示为未监测，不尝试注入进程或修改系统级代理。

## 观测链路

监测启动为 Codex 子进程设置受限的 WebSocket 调试日志环境，读取本机 Codex 日志数据库的追加记录；不建立系统级 HTTPS 代理，不安装根证书，不读取账号凭据。解析器只投影服务端模型、请求模型、响应 ID、线程 ID、轮次 ID、事件时间和完成状态；原始日志正文、提示词、回复、工具参数、工具输出和文件内容不进入任务栏数据目录。Codex 自己的调试日志可能包含原始通信内容并由 Codex 写入其日志数据库；任务栏工具无法替 Codex 删除或阻止这部分落盘，因此监测默认关闭，只有用户明确开启后才生效。

只有出现明确的服务端模型字段时才显示“服务端回报”。缺少字段时显示“未核对”，不使用 turn_context.model 冒充服务端模型。请求模型来自同一响应的请求元数据或关联的任务轮次；无法可靠关联时保留未核对。

监测链路失败、日志结构变化或 Codex 不支持调试字段时，Codex 继续按普通方式运行；任务栏显示“未核对”并保留错误原因的短状态，不保存原始错误正文。

## 保存与隐私

只保存最近 100 条模型核对记录：请求模型、服务端模型、响应 ID、线程/轮次 ID、时间、状态和不一致原因。记录保存在 `%USERPROFILE%/.codex-taskbar-companion`，不上传、不写入诊断快照、不保存正文。关闭监测时停止追加读取；历史记录可在设置中清除。

## 展示

设置的“常规”页提供一个开关和当前状态。开启、等待接管、监测中、未监测和错误使用简短状态文案；启动接管前明确提示将等待空闲并重启 Codex。状态条不增加常驻文字；仅在发现不一致时显示小数量提示。点击现有详情入口打开附加模型核对面板，显示最近记录、请求模型、服务端模型、时间和状态。面板按需打开，沿用现有不透明详情表面和可中断高度动画。

## 验收

- 开关持久化，关闭后不启动监测链路。
- 有运行任务时开启只进入等待状态，不关闭或重启 Codex。
- 解析模拟调试记录时只保留白名单字段，正文和工具内容不落盘。
- 缺少服务端模型时显示未核对；请求模型与服务端模型不一致时显示不一致。
- 监测面板不增加常驻底栏文字，不改变额度、Token、任务搜索和重置行为。
- 本轮只做离线解析、设置、渲染和源码启动验证；不启动、不关闭、不重启用户当前 Codex。真实接管流程由用户后续亲自测试。
