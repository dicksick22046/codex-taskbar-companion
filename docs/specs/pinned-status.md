# Pinned status rows

Replace the independently positioned Running strip with a single lightweight panel attached edge-to-edge to the existing status bar. Each selected nonempty status occupies one 30-DIP row in the existing category order; there are no repeated state headings, counts, projects, times or usage values. A row contains its colored state dot, the task title and an unpin control. Full detail and Main/Side identity remain in the existing status list and tooltips. No Agent children are added.

Each status popover has a top-right Pin/Unpin button. Pinning ensures status counts are enabled, persists the chosen category and closes the full list. The bottom status buttons continue opening full lists. Row title activation opens the selected task; unpin only removes that category. Empty pinned categories hide but retain their preference; pinned empty categories remain reachable from the tray status menu to unpin. Remove the settings switch for the independent strip. Migrate an existing enabled strip to Running pinned; preserve explicit new preferences and discard the obsolete independent position.

The one panel uses the same width, color, opacity and connected edges as the bar; size it from the title and footer requirements below. It follows the bar, cannot be dragged separately, opens above where possible and below near the screen top. Hide it when its bar is unavailable or fullscreen is foreground. Every row independently retains the existing 8-second rotation, interruptible handoff and hover-only long-title scroll. Hover visibly highlights the whole row, pauses its rotation, and gives the pin a separate pressed/hover cue. The pinned-row icon is muted at rest and gains accent color on hover, press or keyboard focus. Press/release target protection, reduced motion, hidden-clock suspension, task removal and language changes must remain correct. Accessible names include category and title without adding visible labels.

Use the existing Provider and shared UI cadence, without new task collection, global pointer input or task execution. Verify preference migration, multiple categories, empty/reappearance, pin/unpin without title activation, status changes during press, independent hover timing, attachment above/below, no separate drag, all four languages, reduced motion and real installed visibility. Tests never consume reset credits.

Full popovers and the context menu are placed outside the combined bar/pinned area, with the existing gap. Popovers reserve an expanding group's target extent and follow size changes; constrained content retains scrolling. Pinned windows are owned by the bar, and an open popover is owned by the visible pinned group (or the bar when no group is visible). Repair broken relative order without activation, changing unrelated window order, or continually forcing topmost; retain the floating topmost preference.

The rotating footer treats each label/value pair as one compact group with a 3-DIP gap. Status pills form a separate group aligned to the right inset, rather than inheriting spare title width as trailing whitespace. Reserve the widest complete metric pair for stable rotation, not the sum of independent widest labels and values. The ring stays fixed. Pinned title width is measured across the current candidates and can shrink the former 240-DIP minimum, capped at that previous allowance; footer requirements still take priority. Do not resize for each rotated task or quota item.

Reuse existing taskbar mouse-release observation and native Z-order-change messages to coalesce one immediate layer/paint reconciliation after shell activation. Preserve foreground focus, avoid extra polling, and suppress re-entry from the repair's own window changes. Periodic checks remain the fallback.

## Running feedback and optional metric names

Running status dots in the footer and attached running row breathe gently in the same phase. A soft highlight travels across the running row without shifting its text or controls. Other categories remain still. Reuse the existing 33ms paint clock, repaint only affected visible regions, stop when hidden or no running item remains, and honor reduced motion. Hover reading pauses the travelling highlight, while the running dot still communicates activity. Preserve existing ring interpolation and task handoff.

Settings > Indicators adds “Show indicator names”, default on, stored as `show_metric_labels`. Turning it off removes only metric captions in both rotating and simultaneous layouts; retain rings, numbers, units, full accessible names and panel headings. Changes apply and resize immediately, preserve the selected metric, and settle any in-flight caption handoff. All four interface languages include this setting. It is independent of the five visibility toggles, so it cannot keep an otherwise disabled bar visible.
