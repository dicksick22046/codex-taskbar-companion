# 开发交接

## 产品与范围
Codex Taskbar Companion，版本0.1.4。目标是Windows11 x64上极简Codex额度与任务状态条；不做多服务商、美元成本仪表盘、macOS或完整实时错误捕获。行为以status-bar.md和release-v0.1.md为准。

## 已实现
- 周额度、可用时自动展示5h额度、倒计时、日额度消耗；稳定圆环，仅数据变化平滑过渡。
- 任务轮播、每日时长/Token、待读、明确停止/失败和任务跳转。主栏标题按字形中心对齐。
- 两个独立面板；任务行信息组以短竖线、紫色时长和蓝色Token分开，宽度自适应。
- 右键菜单仅设置/退出；五项显示开关、开机启动和检查更新集中在设置；托盘和重复启动都能找回设置。
- 任务栏左侧空间不足收起到托盘，避免遮挡系统按钮。
- 每用户Inno Setup安装；数据位于USERPROFILE/.codex-taskbar-companion，升级/卸载保留设置和历史。
- 版本号统一；GitHub稳定Release检查、校验下载、等待旧进程退出后安装并重启。更新源dicksick22046/codex-taskbar-companion。

## 已知边界
- 额度来自账户，本机Token来自本地日志，二者范围不同。日额度从首个样本起算，缺失区间不估算。
- 只读服务会将外部活动轮次投影成interrupted，不能用它判断停止；停止依据明确日志，失败依据匹配轮次的failed与error。
- 完整实时失败事件接入已由用户取消，不再列为首版阻塞工作。
- 首版未在Win10、Mac、多屏独立组件或全新电脑上验收。0.1.4已公开发布，GitHub构建与公开下载校验通过。


## 重启后日额度归零修复
旧LocalAppData逻辑地址会在宿主环境中映射到Codex包LocalCache，正常启动可能使用另一份记录。数据改到USERPROFILE/.codex-taskbar-companion；已用实际文件句柄路径确认位于用户目录而非包缓存。启动合并可见的旧记录，按时间和周期去重，已有新记录优先，旧文件不删除。额度写入使用临时文件、fsync和原子替换。
已验证旧历史基线恢复、应用重启后保持和实际窗口显示；未执行整机重启。0.1.1安装包已更新并在本机运行。


## 短暂读取失败修复
0.1.2将额度、目录和附加轮次读取分开处理；单次任务查询异常不清空额度，额度超时/空回应保留未过期记录，跨重置时间的旧窗口不继续使用。0.1.3移除失败时的调暗效果，显示保持原样。额度失败仍按30秒节奏重试；附加轮次失败保留已知状态。队列等待超时现在带调用名称，异常来源记录本机日志。
57项测试通过，覆盖额度超时、空回应、目录和附加查询超时及过期窗口。实际测试只中止了状态条自己的只读app-server子进程，20秒画面中额度保留，随后观察到错误标记清除和正常刷新。该断连日志来自受控测试，不能冒充用户原截图的具体网络原因。修正版已安装。

## 登录自启的宿主隔离问题
2026-09-08实际登录后组件没有进程。宿主内能读到Run项，但系统Win32_StartupCommand看不到；Shell-Core登录日志也没有执行该命令。系统StdRegProv同样查不到组件卸载登记。此前通过NtQueryKey读到逻辑路径不能证明已写入系统视图。

使用无登录触发器的临时Windows任务，从Codex宿主外重新执行原有0.1.4安装器后，系统启动项枚举和卸载登记均能读到组件。随后从宿主外启动组件，移除临时任务，程序仍存活、窗口可见、额度刷新正常。安装包与程序代码未变，不增加自启守护或重试进程。

后续安装验收须比较系统接口，不能只在同一宿主内读回。修复后的下一次真实登录仍需观察；此前偶发退出没有足够日志确认原因，不能将其直接认定为同一问题。
